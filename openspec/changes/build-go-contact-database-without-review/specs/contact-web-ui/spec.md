# Spec Delta

## Purpose

Даёт пользователю браузерный интерфейс для сохранения контактов и поиска в обоих направлениях без написания запросов к программному API.

## ADDED Requirements

### Requirement: Ready-to-use browser interface
Система SHALL отдавать браузерный интерфейс с главной страницы того же сервера, что обслуживает API. Страница SHALL содержать явно подписанные поля и действия добавления и поиска на русском языке, работать с клавиатуры и отображаться без горизонтальной прокрутки при ширине окна от 360 CSS-пикселей. Для работы SHALL не требоваться внешние CDN.

#### Scenario: First visit
- **GIVEN** оператор запустил сервер и сообщил пользователю его локальный адрес
- **WHEN** пользователь открывает главную страницу
- **THEN** видит форму добавления и поиск с выбором «По имени» / «По телефону»
- **AND** может перейти к полям и кнопкам клавишей Tab и отправить форму клавишей Enter

### Requirement: Add a contact with truthful feedback
Пользователь SHALL иметь возможность ввести имя и телефон и сохранить контакт. Интерфейс SHALL показывать успешное сохранение только после `201` от API, отображать сохранённые данные и `id`, а ошибки полей и дубликаты — понятным текстом. Во время запроса повторное нажатие сохранения SHALL быть заблокировано; при ошибке введённые значения SHALL сохраняться.

#### Scenario: Save and find a contact
- **GIVEN** пользователь открыл главную страницу и пара ещё отсутствует в базе
- **WHEN** он вводит `Анна` и `+7 (999) 123-45-67` и нажимает «Сохранить»
- **THEN** после подтверждения API видит сообщение об успехе и сохранённый контакт
- **WHEN** выбирает поиск по имени, вводит `Анна` и нажимает «Найти»
- **THEN** видит сохранённый телефон в результатах
- **WHEN** переключает поиск на телефон и вводит `79991234567`
- **THEN** после поиска видит имя `Анна` с тем же `id`

#### Scenario: Correct an invalid contact
- **WHEN** пользователь пытается сохранить телефон `abc`
- **THEN** интерфейс указывает проблему поля телефона, не показывает успех и сохраняет имя и телефон для исправления
- **WHEN** пользователь исправляет телефон на допустимый и снова сохраняет
- **THEN** успешное подтверждение API отображается как сохранённый контакт

#### Scenario: Recognize a duplicate
- **WHEN** API сообщает, что указанная пара уже существует
- **THEN** интерфейс сообщает «Контакт уже существует», показывает существующий `id` и не сообщает о новой записи

### Requirement: Search both directions and navigate matches
Интерфейс SHALL позволять выбрать одно направление поиска и ввести запрос, пояснять, что имя ищется целиком с учётом регистра, а номер — без учёта форматирования. Результаты SHALL показывать имя и телефон каждого контакта. Действие «Показать ещё» SHALL появляться только при наличии продолжения и добавлять следующую страницу без повторов.

#### Scenario: Shared number with several names
- **GIVEN** один номер сохранён для двух разных имён
- **WHEN** пользователь выбирает «По телефону», вводит номер и запускает поиск
- **THEN** видит оба имени и соответствующие телефоны

#### Scenario: Large set and a new search
- **GIVEN** по имени найдено 125 контактов
- **WHEN** пользователь выполняет поиск с размером страницы по умолчанию и дважды нажимает «Показать ещё» после завершения каждого запроса
- **THEN** последовательно видит 50, 100 и 125 контактов, после последней страницы кнопка исчезает
- **WHEN** выполняет новый поиск или меняет направление
- **THEN** прежние результаты и курсор очищаются, выдача начинается с первой страницы

### Requirement: Distinguish loading empty and failed states
Интерфейс SHALL различать исходное состояние, загрузку, найденные контакты, «Ничего не найдено», ошибку ввода и недоступность сервиса. Ошибка SHALL не отображаться как отсутствие совпадений. Ответ старого запроса SHALL не заменять результаты более нового поиска. После сетевого сбоя сохранения SHALL сообщаться, что результат неизвестен и повтор может обнаружить уже созданный контакт.

#### Scenario: No matches and service failure
- **WHEN** успешный поиск возвращает пустой список
- **THEN** пользователь видит «Ничего не найдено»
- **WHEN** поиск не может завершиться из-за сети или ошибки сервера
- **THEN** пользователь видит сообщение об ошибке и доступное повторное действие, а не сообщение об отсутствии контактов

#### Scenario: Retry an ambiguous save
- **WHEN** соединение обрывается во время сохранения и ответ не получен
- **THEN** интерфейс сохраняет ввод и сообщает о неизвестном результате
- **WHEN** пользователь повторяет сохранение
- **THEN** интерфейс корректно показывает создание либо существующий контакт согласно ответу API

#### Scenario: Ignore an outdated response
- **WHEN** пользователь запускает новый поиск до получения ответа на предыдущий
- **THEN** запоздалый ответ предыдущего запроса не меняет результаты и состояние текущего поиска

### Requirement: Render contact data as text
Интерфейс SHALL показывать имена, телефоны и сообщения API как текст без выполнения содержащейся в них разметки или кода.

#### Scenario: Name contains markup characters
- **GIVEN** сохранено допустимое имя `<b>Анна</b>`
- **WHEN** пользователь находит контакт
- **THEN** видит буквальный текст `<b>Анна</b>`, а не HTML-элемент
