# Tasks

Все пункты относятся к будущей реализации. Сейчас создаются только planning artifacts.

## 1. Модель и контракт данных

- [ ] 1.1 Реализовать запись, ID и общую валидацию/нормализацию из contact-records; проверить таблицей тестов кириллицу, регистр, пробелы, разделители, границы длины и невалидный ввод.
- [ ] 1.2 Определить версионированное двоичное кодирование записи, составных ключей и целого кадра WAL; проверить round-trip, неоднозначные границы, повреждённые длины и контрольные суммы; описать формат в документации движка.

## 2. Дисковые таблицы и ограниченная память

- [ ] 2.1 Реализовать неизменяемые сортированные таблицы с контрольными суммами и дисковым индексом блоков; проверить точечное чтение и диапазон с лимитом на наборе больше кеша, включая повреждённый блок.
- [ ] 2.2 Реализовать ограниченные memtable, кеш и потоковые итераторы по трём пространствам ключей; проверить поиск популярного ключа без материализации всех совпадений и ограничение выделяемых буферов.
- [ ] 2.3 Реализовать потоковое слияние таблиц с удержанием файлов читателями и ограничением параллелизма; проверить эквивалентность результатов до/после слияния, контроль памяти и чтение активного снимка; описать параметры ресурсов.

## 3. Долговечность и восстановление

- [ ] 3.1 Реализовать эксклюзивное открытие каталога, manifest и проверку версии; проверить второй процесс, новый/существующий каталог и отказ на неподдерживаемом формате без изменения файлов.
- [ ] 3.2 Реализовать сериализованную запись WAL, синхронизацию и атомарную публикацию основной записи с обоими индексами; проверить остановки до/после синхронизации и сохранность всех подтверждённых ID.
- [ ] 3.3 Реализовать сброс memtable, устойчивую публикацию manifest, checkpoint WAL и удаление освобождённых файлов; внедрить остановки на каждой границе и проверить старое либо новое полное состояние.
- [ ] 3.4 Реализовать потоковое восстановление WAL с ограниченной памятью; проверить неполный хвост, неверную контрольную сумму, ошибки ввода-вывода и нехватку места без ложного подтверждения и молчаливой потери.
- [ ] 3.5 Документировать гарантии, ограничения носителя, Linux-платформу, штатную остановку и офлайн-копирование/восстановление; проверить процедуру на отдельном каталоге с поиском известных ID после восстановления.

## 4. Сервис записей и конкурентный поиск

- [ ] 4.1 Связать валидацию с движком и создавать независимые записи для повторов пары; проверить одинаковые имена, общие телефоны и точные дубликаты по обоим индексам.
- [ ] 4.2 Реализовать согласованный снимок отдельного чтения, диапазонный поиск и продолжение после ID; проверить 120 совпадений страницами 50/50/20 и новые записи между страницами без повторной выдачи ID.
- [ ] 4.3 Добавить обратное давление и состояние ошибки писателя; проверить десять параллельных клиентов, отсутствие потерь подтверждённых записей и гонок через `go test -race`.

- [ ] 5.2 Реализовать версионированный курсор, связанный с типом и нормализованным ключом поиска; проверить полное прохождение страниц, другой запрос, неверный и чрезмерно длинный курсор.
- [ ] 5.3 Добавить параметры адреса и каталога с loopback по умолчанию; описать запуск и curl-путь разработчика, включая неизвестный исход POST; выполнить примеры против реального дискового сервера и после перезапуска.
