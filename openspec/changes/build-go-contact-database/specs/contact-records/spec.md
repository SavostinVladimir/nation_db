# Spec Delta

## Purpose

Определить однозначное хранение пар «имя — телефон» и точный поиск связанных записей в обоих направлениях для людей и программ.

## ADDED Requirements

### Requirement: Создание записи
Система SHALL создавать неизменяемую запись с уникальным стабильным строковым `id`, одним `name` и одним `phone`. Каждое успешное создание получает новый ID, включая повтор одинаковой пары. Один человек с несколькими телефонами представлен несколькими записями; связь записей с реальными личностями не устанавливается.

#### Scenario: Сохранение и повтор пары
- **WHEN** клиент дважды создаёт пару «Анна Петрова — +7 (999) 123-45-67»
- **THEN** существуют две записи с разными ID и одинаковыми полями; каждую можно получить в результатах поиска

### Requirement: Проверка и нормализация полей
Система SHALL принимать имя после обрезки внешних пробелов длиной 1–256 Unicode-кодовых точек без управляющих символов. Телефон после обрезки SHALL содержать только ASCII-цифры, необязательный начальный `+` и разделители пробел, `(`, `)`, `-`, `.`; допускается 7–15 цифр и до 64 символов исходного значения. Сохраняются обрезанные отображаемые значения. Невалидные данные SHALL отклоняться до записи.

#### Scenario: Невалидный ввод
- **WHEN** имя пустое после обрезки или телефон содержит буквы либо 6 цифр
- **THEN** создание отклонено с указанием поля и причины; записи и частичных индексных записей не появляется

### Requirement: Поиск имён по телефону
Система SHALL искать по полному телефону после удаления начального `+` и разрешённых разделителей, возвращая все соответствующие записи через страницы. Код страны не добавляется; префиксы `8` и `7` не заменяются. Поиск с невалидным телефоном SHALL возвращать ошибку валидации.

#### Scenario: Несколько имён и форматирование
- **WHEN** сохранены «Анна — +7 (999) 123-45-67» и «Борис — 79991234567», а запрос равен `+7-999-123-45-67`
- **THEN** выдача содержит обе записи с их исходными отображаемыми полями и ID

#### Scenario: Нет совпадений
- **WHEN** запрошен валидный телефон, которому не соответствует ни одна запись
- **THEN** результат является пустым списком без ошибки

### Requirement: Поиск телефонов по имени
Система SHALL искать полное имя после обрезки внешних пробелов и перевода Unicode-букв в нижний регистр. Внутренние пробелы сохраняются; `е` и `ё`, транслитерация, подстроки и разные Unicode-композиции не приравниваются. Результат SHALL включать все соответствующие записи через страницы, без объединения одинаковых телефонов. Валидация имени та же, что при создании.

#### Scenario: Одинаковое имя с разными телефонами
- **WHEN** сохранены «Анна Петрова — 79991234567» и «АННА ПЕТРОВА — 79997654321», а запрос равен ` анна петрова `
- **THEN** выдача содержит обе записи с телефонами и ID

#### Scenario: Только полное совпадение
- **WHEN** сохранена «Анна Петрова», а запрос равен `Анна`
- **THEN** эта запись не входит в результат
